# AI Day AX 관점 정리

AI Day는 Industry Day보다 더 플랫폼과 운영에 가까웠다. 실제 사례를 가능하게 만드는 기반, 즉 AgentCore, Strands Agents, SageMaker, Bedrock, Kiro, AI-ready data, 보안, AIOps, 추론 인프라가 반복적으로 등장했다. 이 날의 메시지는 “AI를 써보자”가 아니라 “AI가 계속 쓰일 수 있는 구조를 만들자”에 가까웠다.

## 1. 에이전트는 개발보다 운영이 어렵다

삼성 어카운트의 에이전틱 AIOps 사례는 대규모 서비스 운영에서 AI가 어떤 역할을 할 수 있는지 보여줬다. 장애나 이상 징후를 사람이 모두 확인하는 구조에서, AI가 이벤트를 묶고 원인을 좁히고 조치 후보를 제시하는 방향이다.

우리 회사도 결제, 송금, 인증, 증권, 보험, 가맹점 서비스가 서로 얽혀 있다. 장애가 발생했을 때 영향 범위 파악, 고객 영향 추정, 원인 후보 정리, 공지 초안, 회고 문서 초안 작성은 AX 적용 가치가 높다. 다만 운영 에이전트는 틀리면 위험하므로 실행보다 분석과 제안부터 시작하는 편이 맞다.

## 2. AI-ready data 없이는 Agent Builder도 막힌다

AI Day에서 반복된 데이터 메시지는 중요했다. 에이전트가 업무를 하려면 데이터의 위치, 의미, 권한, 최신성, 출처를 알아야 한다. 데이터가 정리되지 않으면 Agent Builder는 결국 데모 수준에서 멈춘다.

우리 회사에서 전사 AX를 하려면 먼저 AI가 접근 가능한 데이터와 접근하면 안 되는 데이터를 구분해야 한다. 사내 문서, 정책, 장애 이력, 고객센터 FAQ, 개발 문서, API 문서, 금융 상품 설명, 리스크 정책은 각각 권한과 검증 기준이 다르다. RAG나 에이전트를 만들기 전에 데이터 카탈로그와 권한 필터링이 먼저 필요하다.

## 3. AI-DLC는 개인 생산성을 팀 역량으로 바꾸는 방법이다

LG전자 AI-DLC, Kiro, GitLab Duo, Strands Agents 관련 세션들은 개발 과정 전체가 AI 기준으로 바뀌고 있음을 보여줬다. 요구사항 정리, 설계, 코드 생성, 테스트, 배포, 운영 피드백이 하나의 흐름으로 연결된다.

우리 회사 개발자들이 이미 Claude Code나 Cursor를 쓰고 있다면, 이제는 개인별 사용 팁을 넘어서 팀 표준이 필요하다. 어떤 정보는 프롬프트에 넣으면 안 되는지, 어떤 산출물은 AI 초안을 허용하는지, 테스트와 코드 리뷰에서 무엇을 확인해야 하는지, 생성된 코드의 책임은 누가 지는지 정리해야 한다.

## 4. 서버리스와 AI는 내부 업무 플랫폼에 잘 맞는다

완성차 지능형 상품 전략 플랫폼 세션은 서버리스와 AI가 의사결정 지원 플랫폼으로 연결되는 모습을 보여줬다. 여러 데이터 소스를 묶고, 사용자가 자연어로 탐색하고, 결과를 전략 수립에 활용하는 흐름이었다.

우리 회사에서는 금융 상품, 혜택, 가맹점, 사용자 행동, 리스크 지표, 캠페인 성과를 연결해 내부 전략 에이전트를 만들 수 있다. 상품/마케팅/제휴/운영 담당자가 직접 질문하고 초안을 얻되, 민감 데이터 접근과 결과 검증은 플랫폼이 통제하는 구조가 필요하다.

## 5. AI 내재화는 도구 배포가 아니라 일하는 방식의 변화다

20만 Amazonian의 AI 내재화와 Quick Desktop 세션은 전사 확산 관점에서 의미가 컸다. Quick Desktop은 knowledge worker가 기존에 쓰던 문서, 메일, 메시지, 캘린더, 스프레드시트, 대시보드를 연결하고, 개인 업무 맥락을 지식 그래프처럼 이해해 업무를 돕는 방향이었다. 아침에는 밤사이 쌓인 메시지와 이메일을 요약하고, 미팅 전에는 관련 문서와 파일을 모아 발표자료나 보고 문서 초안을 만들고, 퇴근 후에는 사용자가 설정한 작업을 에이전트가 이어서 수행하는 흐름이 소개됐다.

각자가 도구를 흩어져 쓰는 방식은 빠르게 시작할 수 있지만, 조직 역량으로 남기 어렵다. 승인된 데이터, 승인된 도구, 스킬, 로그, 비용 관리가 한곳에 모여야 한다.

사내 AX TF도 비슷한 방향을 고민할 수 있다. 사내 AI 포털 또는 스킬허브를 중심으로 개발자 도구, 사내 LLM, Bedrock 기반 기능, 업무별 에이전트를 연결하면 개인 생산성을 전사 재사용성으로 바꿀 수 있다. 사무직 관점에서는 전날 이후의 주요 이슈, 미처리 결재, 고객/가맹점 이슈, 장애 업데이트, 오늘 회의 준비 항목을 요약해주는 업무형 AI 데스크톱이 현실적인 출발점이 될 수 있다.

## 6. AI Day에서 가져갈 AX 과제

- 운영 에이전트는 실행보다 분석/추천/문서화부터 시작한다.
- Agent Builder 전에 데이터 카탈로그와 권한 체계를 만든다.
- Claude Code 사용 경험을 팀 표준과 보안 기준으로 승격한다.
- 내부 업무 플랫폼은 서버리스와 이벤트 기반 구조로 작게 시작한다.
- AI 도구 확산은 포털, 스킬허브, 로그, 비용 관리까지 포함해 설계한다.

AI Day를 보고 난 결론은 이렇다. AX의 다음 단계는 더 똑똑한 모델을 찾는 것이 아니라, 에이전트가 안전하게 일하고 계속 개선될 수 있는 운영 체계를 만드는 것이다.
