# 1주차: AWS Summit Seoul 2026 전체 정리와 직접 참석 세션 공유

### 활동 단계

- 자산화

### 진행 내용

이번 주에는 AWS Summit Seoul 2026 참석 내용을 바탕으로 AX TF에 공유할 타사 AX/AI 적용 사례를 전체적으로 정리했다.

먼저 Summit에서 확인한 Industry Day와 AI Day 세션을 문서화하고, 이후 주차별로 나누어 공유할 수 있도록 GitHub에 정리 구조를 만들었다. 전체 사례를 한 번에 모두 공유하기보다는, 이번 주에는 직접 참석해서 들은 세션을 중심으로 주요 인사이트를 먼저 정리했다.

### 직접 참석한 주요 세션

- GS SHOP 영상 기반 AI 상품 추천 플랫폼
- K-POP 글로벌 라이브와 AI 자막
- 바비톡 AX 여정
- 빗썸 Claude Code on Amazon Bedrock
- 삼성 어카운트 AIOps
- 완성차 지능형 상품 전략 플랫폼
- 20만 Amazonian의 AI 내재화와 Quick Desktop

### 주요 정리 내용

- AI 활용은 단순 챗봇이나 프롬프트 활용을 넘어 실제 업무 단위와 운영 체계로 확장되고 있음
- GS SHOP 사례에서는 추천을 위한 신호 추출과 메타데이터 설계가 중요하게 보였음
- 빗썸 사례에서는 개발자 AI 도구를 개인 사용으로 방치하지 않고 SSO, 감사 로그, 비용 관리, 보안 정책을 갖춘 내부 플랫폼으로 제공하는 방향이 인상적이었음
- 바비톡 사례에서는 작은 업무 문제에서 시작해 에이전트와 내부 플랫폼으로 확장하는 접근이 참고할 만했음
- 삼성 어카운트 AIOps 사례에서는 장애 탐지, 원인 후보 정리, 운영 문서화처럼 운영 영역에서 AI를 활용할 수 있는 가능성을 확인했음
- Amazon Quick Desktop 사례에서는 knowledge worker가 기존에 쓰는 문서, 메일, 일정, 메시지, 대시보드와 AI가 연결될 때 사무직 업무 효율화 효과가 커질 수 있음을 확인했음

### 직접 참석 세션에서 인상 깊었던 점

이번 주에는 AWS Summit Seoul 2026에서 직접 들은 세션을 중심으로 AX TF에 공유할 내용을 정리했다. 단순히 어떤 기술을 썼는지보다, 각 회사가 AI를 실제 업무와 운영에 연결하는 방식이 인상 깊었다.

#### 빗썸: LLM Gateway를 운영 관점에서 바라본 사례

빗썸 세션에서는 Claude Code를 Amazon Bedrock 기반으로 안전하게 운영하기 위해 LLM Gateway를 두고, SSO, 감사 로그, 비용 관리, 프롬프트 필터링, 모델 라우팅을 함께 설계한 점이 인상 깊었다.

우리 회사에서도 이미 LLM Gateway를 도입해 사용하고 있기 때문에, 타사에서는 이를 어떤 관점으로 운영하고 있는지 볼 수 있었다는 점이 의미 있었다. 단순히 모델 호출을 중계하는 계층이 아니라, 개발자 AI 도구를 안전하게 확산시키기 위한 인증, 권한, 비용, 감사, 정책 통제 지점으로 보고 있었다.

#### 삼성 어카운트 AIOps: 서브에이전트 분리와 사람 중심 운영

삼성 어카운트 AIOps 세션에서는 대규모 서비스 운영에 AI를 적용할 때 에이전트를 역할별로 분리해 운영하는 관점이 인상 깊었다. 하나의 거대한 에이전트가 모든 것을 처리하는 것이 아니라, 상황 분석, 원인 후보 정리, 조치 제안처럼 역할을 나누는 방식이 더 현실적으로 보였다.

또한 AI가 운영자를 대체하는 것이 아니라 사람이 판단할 수 있도록 정보를 정리하고, 사람 중심의 운영 흐름 안에서 AI를 활용하는 방식이 좋았다. AIOps를 바로 자동 조치로 연결하기보다, 운영자가 더 빠르고 정확하게 판단할 수 있도록 돕는 구조가 AX 적용에서도 중요해 보였다.

#### 바비톡: 작고 명확한 문제에서 시작한 AX

바비톡 AX 여정에서는 작은 문제에서 출발해 AI를 적용해본 방식이 인상 깊었다. 처음부터 거대한 플랫폼을 만드는 것이 아니라, 리뷰 검수, 검색, 상담처럼 작고 명확한 문제를 대상으로 빠르게 검증하고 제품화하는 접근이었다.

또한 Agent AI를 배포하고 모니터링하는 관점까지 함께 다룬 점도 의미 있었다. AX 과제도 너무 큰 목표부터 잡기보다, 반복적이고 효과를 측정하기 쉬운 작은 문제에서 시작할 때 빠르게 제품화될 수 있겠다고 느꼈다.

#### K-POP 글로벌 라이브와 AI 자막: 프롬프트와 운영 아키텍처의 결합

K-POP 글로벌 라이브 세션에서는 AI 자막이 거의 실시간으로 생성되는 것을 보면서 운영 아키텍처의 중요성을 느꼈다. 글로벌 라이브 서비스 특성상 DR을 고려한 아키텍처 구성이 필요했고, AI 기능도 운영 안정성 안에서 설계되어야 했다.

특히 자막 품질을 높이기 위해 system prompt, custom prompt, metadata prompt를 나누어 활용한 부분이 인상 깊었다. metadata prompt에 고유명사나 맥락 정보를 넣어 `M card down`처럼 잘못 인식될 수 있는 표현을 `M Countdown`으로 정확히 출력하게 한 사례가 기억에 남았다.

이 방식은 사내에서 스킬이나 에이전트를 만들 때도 참고할 수 있어 보였다. 단순히 프롬프트를 잘 쓰는 것이 아니라, 업무 도메인의 고유명사, 문맥, 출력 규칙을 메타데이터로 관리하면 결과 품질을 높일 수 있을 것 같다.

#### GS SHOP: 문제 정의와 신뢰 가능한 결과 생성

GS SHOP 세션은 새로운 도구를 나열하는 발표가 아니어서 좋았다. 먼저 문제를 정의하고, 영상에서 어떤 데이터를 뽑아야 하는지 정리하고, 이를 추천 시스템과 운영자가 신뢰할 수 있는 방식으로 연결하는 과정이 인상 깊었다.

AI를 적용할 때 중요한 것은 “어떤 모델을 썼는가”보다 “어떤 문제를 풀려고 했고, 어떤 데이터를 만들었고, 결과를 어떻게 신뢰할 수 있게 했는가”라는 점을 다시 느꼈다.

#### 20만 Amazonian의 AI 내재화와 Quick Desktop: 사무직 생산성의 가능성

가장 인상 깊었던 세션은 20만 Amazonian의 AI 내재화와 Quick Desktop 사례였다. 개발자뿐 아니라 사무직 knowledge worker의 생산성을 높이기 위해 기존 업무 도구를 연결하고, 개인별 업무 맥락을 이해하는 방향이 매우 현실적으로 느껴졌다.

Slack 같은 메시지, 문서, 일정, GitHub, PowerPoint 같은 도구를 연결하고, MCP와 유사한 방식으로 여러 업무 도구를 AI가 사용할 수 있게 하는 점이 인상 깊었다. 또한 LLM wiki나 knowledge graph처럼 개인과 조직의 업무 맥락을 쌓아두고, 사용자가 누구와 일하는지, 어떤 방식으로 일하는지, 미팅은 언제 잡는 것이 좋은지, 해당 아젠다에 필요한 자료는 무엇인지 추천해주는 흐름이 좋았다.

회의 아젠다와 발표 자료를 자동으로 만들고, 실제 발표자가 사용한 PPT도 AI로 생성했다는 점이 특히 기억에 남았다. 이런 방식은 회사에 도입하면 비개발자 사무직의 생산성 향상에 큰 도움이 될 수 있을 것 같다.

Quick Desktop은 Google 계정이나 GitHub 계정으로 무료 체험이 가능하다고 들었는데, 실제로 사용해보면서 어떤 업무에 적용할 수 있을지 체험해보면 좋겠다고 생각했다.

#### Strands Agents SDK: 반복적으로 등장한 에이전트 개발 기반

여러 Agent AI 관련 세션에서 Strands Agents SDK가 반복적으로 등장한 점도 기억에 남았다. AgentCore, Bedrock, Kiro, AIOps, 업무 자동화 사례를 들으면서 에이전트를 직접 구현하거나 운영 환경으로 확장할 때 Strands Agents SDK가 중요한 개발 기반으로 사용되는 흐름이 보였다.

아직 직접 사용해보지는 않았기 때문에, 이후 별도로 문서를 찾아보고 간단한 예제를 만들어보면 좋겠다고 생각했다. 사내에서 Agent Builder나 업무형 에이전트를 고민한다면, Strands Agents SDK가 어떤 방식으로 도구 호출, 메모리, 워크플로, 관측성, 배포와 연결되는지 확인해볼 필요가 있다.
