# AWS Summit Seoul 2026 AX 관점 통합 정리

AWS Summit Seoul 2026을 AX 관점으로 다시 보면 흐름이 꽤 선명하다. Industry Day는 여러 회사가 AI를 실제 업무와 고객 경험에 어떻게 넣고 있는지 보여줬고, AI Day는 그 사례를 가능하게 하는 플랫폼, 데이터, 보안, 운영 체계를 다뤘다.

내가 가져가고 싶은 핵심은 하나다. Claude Code, Cursor, Amazon Q, Bedrock, 사내 LLM 도구를 잘 쓰는 것은 AX의 출발점이다. 하지만 전사 AX는 개인 생산성 향상에서 끝나면 안 된다. 반복되는 업무를 스킬로 만들고, 비개발자도 안전하게 조합할 수 있게 하고, 데이터와 권한을 정리하고, 운영과 감사가 가능한 구조로 만들어야 한다.

## 1. Skill Hub부터 시작해야 한다

여러 세션을 보면서 스킬허브가 단순 프롬프트 저장소가 되면 안 된다는 생각이 강해졌다. GS SHOP은 영상에서 추천에 필요한 신호를 뽑았고, 바비톡은 리뷰 검수와 상담 같은 업무 단위를 에이전트로 확장했다. 중요한 것은 AI가 할 수 있는 말을 모으는 것이 아니라, AI가 반복적으로 수행할 수 있는 업무 능력을 정의하는 것이다.

카카오페이에서 스킬허브를 만든다면 다음 항목을 기본으로 잡아야 한다.

- 입력: 어떤 데이터나 문서를 받는가
- 출력: 어떤 형태의 결과를 내는가
- 참조 데이터: 어떤 시스템과 문서를 보는가
- 검증 기준: 맞고 틀림을 어떻게 확인하는가
- Owner: 누가 관리하는가
- 권한: 누가 사용할 수 있는가
- Human review: 사람 승인 없이 사용 가능한가

## 2. Agent Builder는 자유도가 아니라 안전한 조합이 핵심이다

비개발자가 에이전트를 만들 수 있는 플랫폼은 필요하다. 다만 아무 데이터나 연결하고 아무 액션이나 실행할 수 있으면 금융 회사에서는 바로 리스크가 된다. 좋은 방향은 검증된 스킬, 승인된 데이터 커넥터, 허용된 액션을 조합하게 하는 것이다.

처음에는 조회형, 요약형, 분류형, 초안 작성형 에이전트부터 시작하는 것이 맞다. 실행형 에이전트는 승인 절차, 로그, 권한, 롤백 기준이 준비된 뒤에 열어야 한다.

## 3. 금융권 AX는 보안과 개발자 경험을 같이 풀어야 한다

빗썸의 Claude Code on Amazon Bedrock 사례는 카카오페이에 바로 연결된다. 개발자들이 AI 도구를 쓰는 흐름은 이미 시작됐다. 이제 필요한 것은 금지보다 안전한 사용 경로다.

카카오페이에서 고민할 만한 구조는 다음과 같다.

- SSO 기반 인증
- 사내 네트워크 또는 프라이빗 경로
- 모델 사용 로그와 감사 로그
- 팀/개인별 비용 가시화
- 프롬프트와 응답에 대한 보안 필터링
- 팀별 스킬과 시스템 프롬프트 공유
- 모델 라우팅과 사용 정책 관리

이 구조가 있으면 개발자 경험을 크게 해치지 않으면서도 금융권 내부통제 요구를 맞출 수 있다.

## 4. AI-ready data가 AX의 병목이다

AI Day에서 반복된 메시지는 데이터였다. 에이전트는 데이터의 위치, 의미, 권한, 최신성, 출처를 알아야 한다. 이게 없으면 Agent Builder도, RAG도, 업무 자동화도 데모 수준에서 멈춘다.

카카오페이에서는 고객 데이터, 금융 거래 데이터, 내부 정책, 개발 문서, 장애 이력, 고객센터 지식, 상품 설명, 리스크 정책이 모두 다른 민감도를 가진다. AX TF는 “어떤 데이터를 AI가 볼 수 있는가”를 먼저 정리해야 한다. 데이터 카탈로그와 권한 필터링은 플랫폼 후순위가 아니라 선행 조건이다.

## 5. AIOps와 AgentOps는 빠르게 효과를 볼 수 있는 영역이다

삼성 어카운트의 AIOps 사례는 대규모 서비스 운영에서 AI가 현실적인 가치를 낼 수 있음을 보여줬다. 장애 원인 후보 정리, 영향도 분석, 운영 리포트 작성, 조치 후보 추천은 핀테크에서도 바로 떠올릴 수 있는 업무다.

다만 운영 에이전트는 조심스럽게 시작해야 한다. 처음부터 자동 조치까지 가기보다 분석, 요약, 추천, 문서화에서 시작하고 사람이 승인하는 흐름을 두는 것이 안전하다.

## 6. 내부 업무 플랫폼은 작은 실험에서 시작한다

완성차 상품 전략 플랫폼과 Amazon Quick Desktop 사례를 보면서, 전사 AX 플랫폼은 거창한 화면보다 업무 흐름을 얼마나 잘 모으는지가 중요하다고 느꼈다. Quick Desktop은 knowledge worker가 기존에 쓰던 문서, 메일, 메시지, 캘린더, 스프레드시트, 대시보드를 연결하고, 개인 업무 맥락을 지식 그래프처럼 이해해 아침 요약, 미팅 준비, 자료 생성, 이메일 초안, 퇴근 후 자동 작업까지 지원하는 방향이었다. 카카오페이에서도 상품, 마케팅, 제휴, 운영, 개발, 고객센터가 각자 다른 AI 도구를 쓰는 상태가 계속되면 재사용성이 떨어진다.

처음부터 완성형 플랫폼을 만들기보다 다음 정도의 작은 실험이 현실적이다.

1. 부서별 반복 업무를 수집한다.
2. 공통 스킬 후보를 20개 정도 정의한다.
3. 조회형 에이전트 2개와 문서 생성형 스킬 2개를 만든다.
4. 사용 로그, 품질, 비용, 보안 이슈를 모아 운영 기준을 만든다.

## 7. 내가 실제로 들은 세션에서 남은 것

GS SHOP 세션에서는 추천을 위한 신호 추출이 기억에 남았다. 카카오페이의 혜택, 상품, 가맹점 추천도 결국 좋은 메타데이터와 검증 가능한 근거가 있어야 한다.

K-POP 글로벌 라이브 세션에서는 AI 기능보다 운영 안정성이 더 크게 보였다. 금융 서비스에서도 AI 기능은 장애 전환, 비용, 품질 폴백과 함께 설계되어야 한다.

바비톡 세션에서는 작게 시작하는 방식이 좋았다. AX TF도 대형 플랫폼보다 반복 업무 하나를 실제로 줄이는 작은 성공이 먼저 필요하다.

빗썸 세션은 핀테크 회사로서 가장 직접적인 참고 사례였다. Claude Code 같은 개발자 AI 도구를 안전하게 쓰게 만드는 내부 플랫폼은 카카오페이에서도 우선순위가 높다.

삼성 어카운트 AIOps 세션은 대규모 서비스 운영에서 AI가 분석과 조치 후보 추천에 강점을 가질 수 있음을 보여줬다.

완성차 지능형 상품 전략 플랫폼 세션은 내부 의사결정 플랫폼의 가능성을 보여줬다. 금융 상품, 혜택, 제휴, 사용자 행동 데이터를 연결하는 전략 에이전트로 확장해볼 수 있다.

20만 Amazonian과 Quick Desktop 세션은 AI 내재화가 개인 도구 사용을 넘어 회사가 승인한 업무 환경과 스킬 체계로 가야 한다는 점을 보여줬다. 특히 사무직의 업무 효율화는 챗봇 하나를 제공하는 방식보다, 기존 도구를 연결하고 개인 업무 맥락을 유지하면서 하루의 시작과 끝을 도와주는 형태가 더 현실적이다.

## 정리

카카오페이 AX TF에서 바로 논의할 주제는 네 가지라고 본다.

- 사내 스킬허브를 어떤 단위로 만들 것인가
- 개발자 AI 도구를 금융권 기준에 맞게 어떻게 안전하게 제공할 것인가
- AI-ready data와 권한 체계를 어디까지 먼저 정리할 것인가
- AgentOps와 AIOps를 어떤 업무부터 작게 실험할 것인가

AWS Summit에서 본 사례들은 이미 충분히 현실적이었다. 이제 필요한 것은 “AI로 무엇을 할 수 있나”보다 “우리 업무를 어떤 스킬과 운영 체계로 바꿀 것인가”에 가까워 보인다.
