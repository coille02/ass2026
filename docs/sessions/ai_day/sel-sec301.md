## 발표 주제

AI 워크로드 이용환경은 끊임없이 진화하고 변화하고 있습니다. 이러한 환경속에서도 보안은 여러분의 최우선 순위일 수 밖에 없습니다. 이 세션에서는 AI 워크로드를 위한 향상된 보안 아키텍터에 대해 살펴보도록 하겠습니다. 지속적으로 발전하는 지능적인 공격으로부터 여러분의 워크로드를 안전하게 보호할 수 있는 방안에 대한 아이디어를 얻어가시기 바랍니다.

AI 워크로드를 안전하게 운영하기 위한 심층 방어 구조를 AWS 네이티브 서비스와 오픈소스 프레임워크 관점에서 설명했다. 프롬프트 인젝션, 유해 콘텐츠, RAG 권한 필터링, MCP 인증/인가까지 에이전틱 AI 보안의 실전 쟁점을 다뤘다.

## 주요 내용

- 자연어 입력은 모델 내부에서 해석되므로 보안 통제는 모델 외부에서 강제해야 함.
- Amazon Bedrock Guardrails는 책임 있는 AI 정책, 콘텐츠 필터, 민감정보 차단, 주제 차단에 활용.
- RAG는 검색 후 필터링, 사용자/그룹별 데이터 분리, 메타데이터 기반 검색 전 필터링 등 권한 전략이 필요.
- MCP 환경에서는 OAuth 기반 2-legged/3-legged 인증 패턴으로 도구 접근을 안전하게 위임해야 함.

## 세부 내용

### 문제의식과 배경

자연어 입력은 모델 내부에서 해석되므로 보안 통제는 모델 외부에서 강제해야 함. Amazon Bedrock Guardrails는 책임 있는 AI 정책, 콘텐츠 필터, 민감정보 차단, 주제 차단에 활용.

### 접근 방식과 아키텍처

RAG는 검색 후 필터링, 사용자/그룹별 데이터 분리, 메타데이터 기반 검색 전 필터링 등 권한 전략이 필요. MCP 환경에서는 OAuth 기반 2-legged/3-legged 인증 패턴으로 도구 접근을 안전하게 위임해야 함.

### 운영 포인트와 확장 방향

관련 기술 키워드는 Amazon Bedrock Guardrails, RAG 보안, MCP, OAuth, 데이터 거버넌스, Prompt Injection, 심층 방어이다.

## 정리

이 세션의 핵심은 AI 보안심화: AI 워크로드에 대한 심층방어 체계 구축를 단순한 기능 소개가 아니라 실제 업무와 운영 환경에 적용하기 위한 조건으로 풀어냈다는 점이다. 자연어 입력은 모델 내부에서 해석되므로 보안 통제는 모델 외부에서 강제해야 함.

발표는 AI 활용의 속도를 높이더라도 보안, 접근 제어, 감사, 데이터 보호를 같은 수준으로 설계해야 한다는 메시지로 정리된다.
