## 발표 주제

이 세션은 Amazon Bedrock 기반 생성형 AI 프로젝트에서 환각을 운영 수준으로 통제하는 방법을 설명한 발표다. 스마일샤크는 매경AX와 구축한 AI 팟캐스트·콘텐츠 생성 사례를 통해, 대본 생성 과정에서 원문 사실이 바뀌는 문제를 어떻게 평가 모델과 사람 검수, 운영 루프로 다뤘는지 소개했다.

발표의 중심은 환각 통제가 한 번의 프롬프트 수정이 아니라 생성, 평가, 재생성, 사람 검수, 평가 기준 보정이 반복되는 LLMOps 문제라는 점이다.

## 주요 내용

- 운영 가능한 GenAI 서비스의 핵심은 자연스러운 문장 생성보다 원문 사실과 의미를 보존하는 품질 관리라고 설명했다.
- 초기 워크플로는 기사 선별, 대본 생성, 통합, TTS 변환으로 구성됐고 AWS Step Functions로 전체 흐름을 제어했다.
- 가장 큰 병목은 대본 생성 과정에서 원문의 사실 관계나 의미가 바뀌는 환각 문제였다.
- 코드 기반 평가는 빠르지만 의미 보존을 판단하기 어렵고, 사람 기반 평가는 정확하지만 대량 운영에 부담이 크다고 설명했다.
- LLM 기반 평가 모델을 도입해 기사와 대본을 문장 단위로 비교하고 pass/fail과 근거를 생성하도록 설계했다.
- 생성 모델과 평가 모델을 같은 계열로만 쓰면 동일한 편향을 놓칠 수 있어 교차 모델 평가로 사각지대를 줄였다.
- 사람과 평가 모델의 판단 차이를 수집해 평가 기준과 모델을 보정하고, 비용과 품질을 함께 관리하는 운영 체계를 제시했다.

## 세부 내용

### 콘텐츠 생성 워크플로

발표자는 AI 팟캐스트와 콘텐츠 생성 흐름을 기사 선별, 대본 생성, 통합, TTS 변환 단계로 설명했다. AWS Step Functions는 이 단계들을 연결하고, 각 단계의 성공과 실패를 제어하는 오케스트레이션 역할을 맡았다.

문제는 대본 생성 단계였다. 생성형 AI가 문장을 자연스럽게 만들더라도 원문의 사실이나 의미가 바뀌면 콘텐츠 서비스로는 사용할 수 없다. 이 때문에 품질 기준은 문장의 유창함보다 원문 보존과 사실 정확성에 놓였다.

### LLM 기반 평가와 교차 검증

스마일샤크는 기사 원문과 생성 대본을 문장 단위로 비교하는 LLM-as-a-Judge 구조를 소개했다. 평가 모델은 각 문장이 원문 의미를 유지했는지 판단하고, 문제가 있는 경우 근거를 함께 제공한다. 해결되지 않는 항목은 사람 검수로 넘기는 방식이다.

평가 모델도 틀릴 수 있기 때문에 교차 모델 평가가 필요하다고 설명했다. 생성 모델과 같은 계열의 모델만 평가에 쓰면 동일한 편향을 공유할 수 있으므로, 다른 모델을 함께 사용해 놓치는 문제를 줄이는 접근이다.

### 운영 루프와 품질 관리

발표 후반부는 평가 모델을 한 번 만들고 끝내는 것이 아니라 운영 중 계속 보정해야 한다는 점을 강조했다. 사람과 평가 모델의 판단이 다른 데이터를 모아 기준을 조정하고, 평가 모델을 개선하며, 재생성 여부와 사람 검수 범위를 조절한다.

또한 운영 시스템에서는 품질뿐 아니라 비용도 함께 봐야 한다. 평가와 재생성을 많이 할수록 품질은 올라갈 수 있지만 비용과 지연시간도 증가하기 때문에, 서비스 수준에 맞는 균형이 필요하다는 메시지가 제시됐다.

## 정리

이 세션의 핵심은 생성형 AI 신뢰성이 프롬프트 하나로 해결되지 않는다는 점이다. 환각 통제는 생성 결과를 평가하고, 필요한 경우 재생성하며, 사람 검수 데이터를 다시 평가 기준에 반영하는 운영 시스템에 가깝다.

스마일샤크 사례는 Amazon Bedrock과 Step Functions, LLM-as-a-Judge, 교차 모델 평가, Human Review를 결합해 운영 가능한 품질을 만드는 방식을 보여줬다. 생성형 AI 품질은 모델이 만든 답을 또 다른 모델과 사람이 함께 검증하는 루프에서 나온다는 메시지가 선명했다.
