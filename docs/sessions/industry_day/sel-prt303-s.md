## 발표 주제

이 세션은 LLM과 에이전트 워크로드에서 GPU를 더 세밀하고 지능적으로 할당하기 위한 Kubernetes Dynamic Resource Allocation(DRA) 기반 운영 방식을 소개한 발표다. GPU 부족 자체보다 GPU가 워크로드 특성에 맞지 않게 배치되어 idle, 과점유, 토폴로지 불일치가 생기는 문제가 중심이었다.

발표는 기존 Kubernetes GPU 디바이스 플러그인 방식의 한계, LLM·에이전트 워크로드의 자원 패턴, DRA의 ResourceClaim 모델, MPS·MIG·time slicing·exclusive 사용 전략, EKS GPU 운영 최적화 방향을 다뤘다.

## 주요 내용

- AI 워크로드 환경에서는 GPU 확보량뿐 아니라 GPU를 어떻게 나누고 배치하는지가 비용과 성능을 좌우한다.
- LLM 추론, 모델 서빙, 에이전트 실행은 요청 패턴과 자원 사용량이 동적이어서 고정적인 GPU 할당으로는 비효율이 생기기 쉽다.
- 기존 Kubernetes 디바이스 플러그인은 GPU 개수 중심으로 자원을 표현하기 때문에 메모리, 공유 정책, 토폴로지 요구를 세밀하게 다루기 어렵다.
- DRA는 워크로드가 필요한 GPU 조건을 ResourceClaim으로 선언하고, 스케줄러가 적절한 자원을 연결하는 방식으로 설명됐다.
- MPS, MIG, time slicing, exclusive GPU 사용은 워크로드 특성에 따라 선택해야 하는 공유·격리 전략으로 소개됐다.
- GPU 메모리, 연산량, 지연시간 민감도, 노드 토폴로지를 함께 고려해야 안정적인 LLM·에이전트 운영이 가능하다.
- 발표는 EKS에서 GPU 활용률을 높이고 운영 정책을 표준화하기 위한 차세대 자원 관리 모델로 DRA를 제시했다.

## 세부 내용

### GPU 운영 문제의 변화

발표는 AI 인프라의 문제가 단순히 GPU가 부족한가에서 GPU를 얼마나 잘 쓰는가로 옮겨가고 있다고 설명했다. LLM 서빙이나 에이전트 워크로드는 요청량이 일정하지 않고, 순간적으로 큰 메모리나 연산량을 요구하기도 한다.

GPU를 통째로 할당하면 작은 작업이 큰 GPU를 점유해 idle이 늘고, 반대로 여러 작업을 무리하게 공유하면 지연시간과 안정성이 떨어진다. 따라서 워크로드 특성에 맞는 공유와 격리 정책이 필요하다.

### 기존 디바이스 플러그인의 한계

Kubernetes의 기존 GPU 디바이스 플러그인 방식은 GPU를 몇 개 요청하는지에 초점이 맞춰져 있다. 하지만 실제 운영에서는 GPU 메모리 크기, MIG 파티션, MPS 공유 여부, NUMA와 네트워크 토폴로지, 지연시간 민감도 같은 조건이 중요하다.

발표에서는 GPU 개수만으로는 LLM과 에이전트 워크로드의 요구를 충분히 표현하기 어렵다고 설명했다. 특히 여러 모델과 에이전트가 같은 클러스터에서 실행될 때는 자원 정책이 더 세밀해야 한다.

### DRA 기반 자원 선언

DRA는 워크로드가 원하는 자원 조건을 ResourceClaim으로 선언하고, Kubernetes가 그 조건에 맞는 실제 자원을 연결하도록 하는 방식이다. 이를 통해 GPU를 단순 개수보다 풍부한 속성과 정책으로 표현할 수 있다.

예를 들어 특정 워크로드는 전용 GPU가 필요하고, 다른 워크로드는 MIG나 time slicing으로 충분할 수 있다. DRA는 이런 요구를 스케줄링 단계에서 반영해 자원 낭비를 줄이고 예측 가능한 성능을 만들 수 있게 한다.

### 공유와 격리 전략

발표에서는 MPS, MIG, time slicing, exclusive GPU 사용을 워크로드별로 선택해야 한다고 설명했다. 대화형 에이전트나 경량 추론은 공유 전략이 비용 효율적일 수 있고, 대형 모델이나 지연시간 민감 서비스는 전용 GPU가 더 적합할 수 있다.

운영자는 GPU 활용률만 보는 것이 아니라 실패 격리, 성능 예측 가능성, 모델 간 간섭, 배치 크기, 요청 패턴까지 함께 고려해야 한다. DRA는 이런 정책을 클러스터 운영 모델에 반영하는 도구로 제시됐다.

## 정리

이 세션의 핵심은 AI 인프라 최적화가 GPU 확보 경쟁에서 GPU 운영 정교화로 넘어가고 있다는 점이다. GS네오텍은 DRA를 활용해 LLM과 에이전트 워크로드의 다양한 자원 요구를 Kubernetes에서 더 정확하게 표현하고 배치하는 방식을 제시했다.

발표는 GPU를 더 잘게 나누는 것만이 아니라, 워크로드 특성과 운영 정책에 맞게 더 똑똑하게 할당하는 것이 비용과 성능을 동시에 개선하는 길이라는 메시지를 전달했다.
