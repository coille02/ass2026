# 규제 환경에서의 통제 가능한 AI 에이전트 아키텍처

- 트랙: Track 9

## 발표 주제

이 세션은 공공, 헬스케어 등 규제 환경에서 AI 에이전트를 도입할 때 데이터 보호, 내부통제, 감사 대응을 아키텍처 수준에서 어떻게 설계할지 설명한 발표다. AI 에이전트의 자율성이 생산성을 높이는 동시에 규제 리스크를 키울 수 있으므로, 거버넌스를 사후 문서화가 아니라 설계 입력값으로 다뤄야 한다는 점이 핵심이다.

발표는 규제 환경의 주요 요구사항, AI 에이전트의 데이터 접근과 행동 통제, Amazon Bedrock 관리형 접근과 Amazon EKS 셀프 매니지드 접근 비교, Bedrock Guardrails와 AgentCore Policy를 활용한 통제 구조를 다뤘다.

## 주요 내용

- 규제 환경의 AI 도입 논의는 개인정보 보호, 데이터 분리, 내부통제, 감사 가능성으로 귀결된다고 설명했다.
- 고영향 AI는 설명 가능성, 사람의 개입, 위험관리체계, 활용 고지 같은 요구를 아키텍처에 반영해야 한다.
- AI 에이전트는 어떤 데이터를 볼 수 있는지, 어떤 도구를 실행할 수 있는지, 어떤 단계에서 승인이 필요한지를 명확히 설계해야 한다.
- Bedrock 기반 관리형 접근은 배포와 운영 부담을 줄이고, EKS 기반 셀프 매니지드 접근은 모델과 인프라 통제권을 더 세밀하게 제공한다.
- Bedrock은 고객 데이터가 모델 학습에 사용되지 않는다는 점, 고객 간 데이터 격리, 리전 선택을 통한 데이터 레지던시를 기반으로 제시됐다.
- Bedrock Guardrails는 모델 입출력 통제에, AgentCore Policy는 에이전트 행동 통제에 활용되는 이중 구조로 설명됐다.
- Cross-account Guardrails를 통해 여러 계정의 모델 호출 정책을 중앙에서 강제하는 방식도 소개됐다.

## 세부 내용

### 규제 환경의 요구사항

발표는 규제 환경에서 AI를 도입할 때 먼저 데이터와 책임의 경계를 정의해야 한다고 설명했다. 공공과 헬스케어 같은 영역에서는 개인정보, 민감 정보, 업무 기록, 의사결정 근거가 모두 중요하다.

AI 에이전트는 단순히 답변하는 시스템이 아니라 데이터를 조회하고 도구를 실행할 수 있다. 따라서 에이전트에게 어떤 데이터를 보게 할 것인지, 어떤 행동을 허용할 것인지, 어떤 결과를 감사할 것인지가 설계의 핵심이 된다.

### Bedrock 접근과 EKS 접근

Bedrock 기반 접근은 관리형 서비스의 장점을 활용한다. 모델 호출, 보안 기능, Guardrails, AgentCore 같은 구성 요소를 활용해 운영 부담을 낮출 수 있다. 고객 데이터가 모델 학습에 사용되지 않고, 리전 선택을 통해 데이터 레지던시를 관리할 수 있다는 점도 설명됐다.

EKS 기반 셀프 매니지드 접근은 더 높은 통제권을 제공한다. 조직이 모델 런타임, 네트워크, 배포 방식, 에이전트 프레임워크를 직접 운영해야 하지만, 세밀한 정책과 기존 보안 체계에 맞춘 구성이 가능하다. 발표에서는 조직의 규제 수준과 운영 역량에 따라 선택이 달라진다고 정리했다.

### 모델 입출력과 행동 통제

규제 환경에서는 모델이 어떤 답을 생성하는지뿐 아니라 에이전트가 어떤 행동을 하는지도 통제해야 한다. Bedrock Guardrails는 유해하거나 정책에 맞지 않는 입력과 출력을 제어하는 계층으로 설명됐다.

AgentCore Policy는 에이전트가 호출할 수 있는 도구와 행동 범위를 제한하는 방식으로 소개됐다. 예를 들어 특정 데이터 조회는 허용하되 외부 전송은 제한하거나, 민감 작업은 사람의 승인 이후에만 실행하도록 설계할 수 있다.

### 감사와 운영 검증

발표에서는 책임질 수 있는 에이전트를 만들기 위해 로그와 감사 추적이 중요하다고 강조했다. 누가 어떤 요청을 했고, 에이전트가 어떤 데이터를 참조했으며, 어떤 도구를 호출했고, 어떤 결과가 나왔는지 남겨야 한다.

Cross-account Guardrails와 중앙 정책 관리는 여러 계정과 조직 단위에서 일관된 통제를 적용하기 위한 방법으로 제시됐다. 이는 규제 대응을 개별 애플리케이션의 노력에만 맡기지 않고, 플랫폼 계층에서 강제하는 접근이다.

## 정리

이 세션의 핵심은 규제 환경의 AI 에이전트가 더 똑똑한 답변보다 책임 가능한 행동 구조를 먼저 갖춰야 한다는 점이다. 데이터 접근, 모델 입출력, 도구 호출, 승인, 감사 로그가 모두 아키텍처의 일부로 설계되어야 한다.

발표는 Bedrock과 EKS 접근을 비교하며 조직의 통제 수준과 운영 역량에 맞는 구현 전략을 제시했다. 규제 환경에서 AI 에이전트를 도입하려면 거버넌스를 별도 문서가 아니라 실행 경로 안에 내재화해야 한다는 메시지가 분명했다.
