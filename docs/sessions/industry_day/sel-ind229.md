**핵심 요약**  
롯데백화점은 모바일 앱 기반 쇼핑 경험을 단순 FAQ 챗봇에서 고객 의도를 이해하고 행동하는 AI 컨시어지 “더스틴”으로 확장한 과정을 공유했다. 발표는 챗봇에서 LLM, 다시 AI 에이전트로 진화한 흐름을 짚고, 700만 고객 규모의 리테일 서비스에서 정보 파편화, 반복 문의, 최신 데이터 반영 문제를 어떻게 풀었는지 설명했다. 더스틴은 고객 경험뿐 아니라 직원 업무 효율과 파트너 협업까지 겨냥한 운영 엔진으로 설계됐다. 비용과 응답 속도를 위해 정적 정보와 동적 정보를 분리하고, 필요한 필드만 LLM 컨텍스트에 넣는 최적화가 강조됐다.

**주요 포인트**
- 롯데백화점의 AI 미션은 AI 자체가 목적이 아니라 고객 경험, 직원 효율, 파트너 협업을 높이는 도구로 쓰는 것이다.
- 더스틴은 매장 위치, 행사, 운영 정보, 외국어 응대 등 백화점 특유의 복잡한 정보를 고객 맥락에 맞게 연결한다.
- 아키텍처는 CloudFront와 웹 애플리케이션 진입, 데이터/검색 계층, 에이전트 상태 관리, 프론트엔드 카드 UI 분리를 포함한다.
- 정적 정보는 앞단에, 자주 바뀌는 동적 정보는 뒤단에 두어 입력 토큰과 지연시간을 줄였다.
- 검색 결과 전체를 LLM에 넣지 않고 답변 생성에 필요한 핵심 필드만 사용해 비용, 품질, 환각 방지를 동시에 고려했다.

**AWS/기술 키워드**  
AI Agent, LLM, Amazon S3, Amazon CloudFront, OpenSearch, RAG, 에이전트 상태 관리, 토큰 최적화, 다국어 쇼핑 컨시어지

**현장 메모로 남길 점**  
“정적인 것은 앞에 두고 동적인 것은 뒤에 둔다”는 설계 원칙이 실무적으로 좋았다. 리테일 AI 사례를 쓸 때 고객-facing 챗봇이 아니라 데이터 운영, UI 상태, 비용 최적화까지 포함한 제품화 사례로 다루면 풍성하다.

**블로그용 한줄**  
롯데백화점의 더스틴은 FAQ 챗봇을 넘어, 백화점의 복잡한 현장 데이터를 고객 경험으로 바꾸는 AI 컨시어지였다.
