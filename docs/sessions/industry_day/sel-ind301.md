**핵심 요약**  
넥슨은 59개 라이브 게임의 장애 대응을 통계 모델과 LLM 기반 다중 에이전트로 재설계한 에이전틱 Ops 사례를 공유했다. 기존에는 운영자가 알람을 보고 직접 판단했지만, 새 구조에서는 이상탐지와 맥락 요약, 전문가 에이전트의 리포트, 리드 에이전트의 취합 판단이 하나의 시스템으로 이어진다. 발표에서는 약 18만 개의 통계 모델이 대규모 이상탐지 백본으로 동작하며 LLM에 넣을 정보를 압축한다는 점을 강조했다. 결과적으로 에이전트가 반복 판단의 상당 부분을 자동 처리하고, 운영자는 실행자에서 감독자로 이동한다는 메시지가 핵심이었다.

**주요 포인트**
- 넥슨은 59개 라이브 게임을 24/365로 운영하며, 알람과 지표의 폭증으로 기존 Ops 방식이 임계점에 도달했다고 설명했다.
- 에이전트가 90% 이상을 자동 처리하면서 운영자가 전략적 업무에 쓸 수 있는 시간이 10%에서 55% 수준으로 늘었다고 소개했다.
- 동시접속자, 매출, 사용자 동향, 서버 지표 등 여러 전문가 모델/에이전트가 상황을 다각도로 진단한다.
- 약 18만 개의 백본 통계 모델이 원천 지표를 바로 LLM에 넣는 대신 의미 있는 맥락으로 증류한다.
- MCP 형태의 인터페이스와 에이전트 구조를 통해 내부 직원이 리포트 생성과 진단을 확장할 수 있는 방향을 제시했다.

**AWS/기술 키워드**  
Amazon Bedrock, LLM, Multi-Agent, AIOps, MCP, Anomaly Detection, Statistical Model, Context Lake, Self-Healing Ops, 24/365 Operations

**현장 메모로 남길 점**  
“분석 도구”가 아니라 “판단 시스템”이라는 표현이 세션을 관통했다. 통계 모델이 LLM의 입력을 압축하고 에이전트가 판단을 조율하는 구조가 핵심이므로, 블로그에서는 LLM 단독 자동화가 아니라 통계+LLM+에이전트 협업으로 설명해야 한다.

**블로그용 한줄**  
넥슨의 에이전틱 Ops는 새벽 3시의 장애 알람을 사람이 혼자 판단하던 시대에서 통계 모델과 AI 에이전트가 함께 판단하는 시대로 옮겨갔다.
