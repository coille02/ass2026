# 당근의 CloudHSM/KMS기반 대규모 서명키관리 시스템구축기

## 세션 정보

- 시간: 2026-05-20 14:30-15:10 KST
- 트랙: Track 2
- 발표자: 박진현(솔루션즈 아키텍트, AWS), 조승환(Identity Service Engineer, 당근), 최용환(Site Reliability Engineer, 당근)

## 발표 주제

이 세션은 당근이 대규모 인증 트래픽을 처리하는 환경에서 서명키 유출 위험을 줄이고 JWT 서명을 안정적으로 운영하기 위해 AWS CloudHSM과 KMS 기반 하이브리드 키 관리 시스템을 구축한 과정을 소개한 발표다. 키를 안전하게 저장하는 것을 넘어, 추출 불가능성, 접근 제어, 고가용성, 관측성, 무중단 전환까지 운영 전체를 설계한 사례다.

발표는 서명키 관리의 위험, 기존 구조의 한계, CloudHSM과 KMS 선택 기준, EKS와 Istio 기반 접근 제어, PKCS#11 운영 이슈, KMS fallback, JWT kid 기반 키 로테이션과 무중단 전환을 다뤘다.

## 주요 내용

- 당근은 MAU 2,100만 규모 서비스에서 하루 평균 수천만 건의 인증 요청을 처리하는 환경을 전제로 서명키 관리 문제를 설명했다.
- 서명키는 JWT, 코드 서명, TLS 인증서 등 신뢰 체계의 뿌리이며, 단 하나의 키 유출만으로도 인증 체계가 무력화될 수 있다.
- 기존 private key가 Secrets Manager에 있는 구조는 접근 권한이 있으면 추출 가능성이 남아 있었다.
- 요구사항은 private key가 외부로 유출되지 않을 것, 6,000 RPS 수준 서명 트래픽을 감당할 것, SPOF가 없을 것, 접근 제어가 촘촘할 것, 담당자도 임의 서명할 수 없을 것이었다.
- CloudHSM은 VPC 내부 배치, PKCS#11 표준 인터페이스, 싱글 테넌트, 고트래픽 비용 효율성 때문에 메인 서명 백엔드로 선택됐다.
- KMS는 장애 시 fallback을 위한 standby로 구성되어 운영 중 HSM 통신 장애 상황에서도 사용자 영향 없이 서비스를 유지한 사례가 소개됐다.
- EKS, Istio Authorization Policy, 보안 그룹, mTLS, IRSA, CloudTrail, Kyverno 정책을 조합해 접근 경로를 다층으로 제한했다.

## 세부 내용

### 서명키 관리의 위험

발표는 서명키가 인증과 신뢰 체계의 핵심이라는 점에서 시작했다. JWT 서명키가 유출되면 공격자가 정상 토큰처럼 보이는 값을 만들 수 있고, 코드 서명키나 인증서 키가 유출되면 더 넓은 공급망 리스크로 이어질 수 있다.

당근의 기존 구조에서는 private key가 Secrets Manager에 저장되어 있었고, 권한을 가진 주체가 키 값을 읽을 수 있는 가능성이 남아 있었다. 발표에서는 보안 수준을 높이기 위해 키가 외부로 추출되지 않는 구조가 필요했다고 설명했다.

### CloudHSM과 KMS 하이브리드 구조

CloudHSM은 키가 HSM 안에서 생성되고 외부로 추출되지 않는 구조를 제공한다. 또한 VPC 내부에서 동작하고 PKCS#11 표준 인터페이스를 활용할 수 있어 애플리케이션과 연동하기 좋다. 고트래픽 환경에서는 KMS 호출 비용보다 CloudHSM의 시간당 과금 구조가 유리할 수 있다는 판단도 소개됐다.

다만 CloudHSM만으로 구성하면 장애 대응 측면에서 부담이 생길 수 있다. 당근은 KMS를 standby fallback으로 두어 HSM 통신 장애 상황에서도 서명 서비스를 유지하도록 설계했다. 실제 운영 중 HSM 통신 문제가 발생했을 때 KMS fallback으로 사용자 영향을 줄인 사례가 핵심 성과로 제시됐다.

### 접근 제어와 운영 통제

서명 서비스는 EKS 위에서 운영되며, 접근 경로는 여러 계층으로 제한됐다. Istio Authorization Policy, 보안 그룹, mTLS, IRSA, IAM 정책, Kyverno 정책을 조합해 애플리케이션과 HSM 사이의 통신 주체를 엄격히 통제했다.

CloudTrail은 키 사용과 관리 이벤트의 감사 추적에 활용되고, Secret Manager와 IAM은 애플리케이션 자격 증명과 권한 관리에 쓰인다. 발표에서는 담당자도 임의로 서명할 수 없도록 운영 권한을 분리하는 점이 강조됐다.

### 실전 운영 이슈와 무중단 전환

운영 과정에서는 PKCS#11 세션 고정, scale-in 시 in-flight 요청 오류, max sessions 튜닝, 바이너리 로그 관측성 부족 같은 문제가 발생할 수 있다. 발표에서는 테스트와 로그 수집 컴포넌트를 통해 이런 이슈를 해결했다고 설명했다.

전환 과정에서는 JWT kid 기반 키 로테이션이 중요했다. 기존 수천만 토큰을 깨지 않으면서 HSM, KMS, 기존 local key가 공존하도록 만들고, 점진적으로 신규 시스템으로 이동하는 방식으로 무중단 전환을 수행했다.

## 정리

이 세션의 핵심은 서명키 보안을 저장 위치의 문제가 아니라 전체 운영 아키텍처의 문제로 다뤘다는 점이다. 당근은 CloudHSM과 KMS를 조합해 키 추출 방지, 고가용성, 비용 효율, 접근 제어, 감사 추적, 무중단 전환을 함께 설계했다.

발표는 대규모 인증 시스템에서 보안성과 안정성을 동시에 달성하려면 HSM 도입뿐 아니라 애플리케이션 접근 경로, fallback, 관측성, 키 로테이션까지 함께 고려해야 한다는 점을 보여줬다.
