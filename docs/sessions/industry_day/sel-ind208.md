## 발표 주제

이 세션은 KB국민은행이 자체 BaaS 플랫폼인 KBaaS를 중심으로 임베디드 금융을 확장하고, 이를 뒷받침하는 API 인프라를 클라우드 네이티브 구조로 현대화한 과정을 소개한 발표다. 결제, 예금, 인증 같은 금융 기능이 비금융 플랫폼 안에서 API로 호출되는 흐름이 커지면서, API 인프라가 금융 서비스의 제품 경쟁력과 운영 안정성을 좌우하는 기반이 됐다는 문제의식에서 출발했다.

발표는 KBaaS의 비즈니스 배경, 기존 3rd Party API 게이트웨이 운영의 한계, 자체 개발 게이트웨이 전환, Amazon EKS 기반 인프라 설계, 데이터베이스와 캐시 전략 검증, 운영 비용과 성능 개선 효과를 순서대로 다뤘다.

## 주요 내용

- KBaaS는 비금융 플랫폼이 KB국민은행의 금융 기능을 API로 호출할 수 있게 하는 임베디드 금융 플랫폼이다.
- 발표에서는 KBaaS가 1,800여 개 API와 일 2억 건 규모의 호출을 처리하는 대규모 API 인프라라고 설명했다.
- 기존 외부 API 게이트웨이 솔루션은 초기 운영 부담을 낮췄지만, 비용, 신규 요구 대응 속도, 보안 취약점 조치, 제휴 확장성에서 제약이 있었다.
- KB국민은행은 자체 개발 게이트웨이를 만들고 Amazon EKS 기반 클라우드 네이티브 구조로 전환해 서비스별 확장성과 배포 유연성을 높였다.
- ALB와 Kubernetes 노드 그룹을 활용해 트래픽 경로와 서비스 특성에 맞는 스케일아웃 구조를 설계했다.
- Aurora DB, 내부 캐시, 분산 캐시 조합을 성능과 비용 관점에서 검증해 과도한 캐시 의존을 줄이고 운영 단순성을 확보했다.
- 인프라 현대화는 단순 비용 절감보다 금융 API를 빠르게 바꾸고 안정적으로 확장하기 위한 전략적 선택으로 설명됐다.

## 세부 내용

### 임베디드 금융과 KBaaS

발표 초반에는 임베디드 금융의 의미를 정리했다. 금융 서비스가 은행 앱 안에서만 제공되는 것이 아니라 쇼핑, 모빌리티, 생활 플랫폼 같은 외부 접점 안으로 들어가면서, 금융사는 API를 통해 결제, 예금, 인증, 조회 같은 기능을 안정적으로 제공해야 한다.

KB국민은행의 KBaaS는 이런 흐름에 대응하기 위해 만들어진 플랫폼이다. 발표에서는 KBaaS를 금융 기능을 API 상품처럼 제공하는 기반으로 설명했다. 중요한 점은 API 개수가 늘어나는 것보다, 제휴사와 고객 접점이 늘어날수록 변경 요구와 트래픽 패턴이 빠르게 달라진다는 점이다.

### 기존 구조의 한계와 자체 게이트웨이

기존 3rd Party API 게이트웨이는 표준 기능을 빠르게 적용하는 데 유리했지만, 대규모 금융 API 운영에서는 한계가 분명해졌다. 라이선스와 운영 비용이 커지고, 신규 제휴 요구나 보안 조치가 솔루션의 기능과 릴리스 주기에 영향을 받았다.

KB국민은행은 게이트웨이를 자체 개발하면서 라우팅, 인증, 로깅, 정책 적용, 배포 방식을 서비스 요구에 맞게 세밀하게 조정할 수 있게 했다. 발표에서는 자체 구축이 비용 절감만을 위한 선택이 아니라, 금융 API의 변경 속도와 통제력을 확보하기 위한 결정이었다고 설명했다.

### EKS 기반 아키텍처

현대화된 구조는 Amazon EKS를 중심으로 구성됐다. ALB가 경로와 서비스 유형에 따라 적절한 노드 그룹으로 트래픽을 전달하고, Kubernetes 기반으로 서비스별 확장과 배포를 관리한다. 이를 통해 특정 API나 제휴 서비스의 트래픽이 급증해도 전체 시스템에 미치는 영향을 줄일 수 있다.

발표에서는 클라우드 네이티브 전환 과정에서 네트워크 경로, 테스트, 배포 단위, 장애 격리 같은 요소를 함께 검토했다고 설명했다. API 인프라가 금융 서비스의 전면에 놓이기 때문에, 단순히 컨테이너로 올리는 것보다 운영 구조를 함께 바꾸는 것이 중요했다.

### 데이터베이스와 캐시 전략

성능 최적화 파트에서는 Aurora DB와 캐시 조합을 검증한 과정이 소개됐다. API 호출량이 크면 모든 요청을 데이터베이스로 보내기 어렵지만, 분산 캐시를 과도하게 쓰면 비용과 운영 복잡도가 커진다.

KB국민은행은 내부 캐시, 분산 캐시, Aurora DB 조합을 비교하며 응답 속도와 비용의 균형점을 찾았다. 발표에서는 캐시를 무조건 늘리는 방식보다, 실제 트래픽 특성과 데이터 접근 패턴에 맞춰 필요한 지점을 선별하는 접근이 강조됐다.

## 정리

이 세션의 핵심은 임베디드 금융이 확산될수록 API 인프라가 금융사의 핵심 제품 인프라가 된다는 점이다. KB국민은행은 KBaaS를 통해 금융 기능을 외부 플랫폼으로 확장하면서, 자체 게이트웨이와 EKS 기반 구조로 성능, 비용, 보안 대응, 제휴 확장성을 함께 개선했다.

발표는 금융 API 현대화가 단순한 인프라 교체가 아니라 비즈니스 확장 방식의 변화라는 점을 보여줬다. API를 안정적으로 운영하고 빠르게 바꿀 수 있는 구조가 임베디드 금융 시대의 중요한 경쟁력이 된다.
