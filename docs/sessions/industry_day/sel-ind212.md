# [AB180] AB180이 SaaS 에이전틱 AI를 설계하는 방법

## 세션 정보

- 시간: 2026-05-20 12:50-13:30 KST
- 트랙: Track 4
- 발표자: 김진아(솔루션즈 아키텍트, AWS), 이승헌(프로덕트 오너, AB180)

## 발표 주제

이 세션은 AB180이 RAG 기반 챗봇 ASK Airbridge에서 출발해, 실제 마케팅 업무 수행을 돕는 SaaS 에이전틱 AI인 Airbridge Pilot으로 발전시킨 과정을 소개한 발표다. 단순 질의응답 챗봇이 아니라 고객의 목표, 캠페인 데이터, 제품 기능을 이해하고 필요한 도구를 호출해 업무를 수행하는 에이전트형 SaaS 경험이 중심이다.

발표는 초기 챗봇의 한계, 에이전틱 AI의 제품적 의미, MCP 기반 도구 연결, Amazon Bedrock AgentCore 활용, 보안과 비용 관리, 평가 체계와 SaaS 사업자의 책임을 차례로 다뤘다.

## 주요 내용

- AB180은 2024년 11월 RAG 기반 챗봇 ASK Airbridge를 출시했지만 유효 답변율이 30% 미만이라 사람의 개입이 필요했다.
- Airbridge Pilot은 답변 중심 챗봇에서 목표 수행형 에이전트로 발전한 사례로 소개됐다.
- 발표에서는 답변 성공률을 28% 수준에서 91% 이상으로 끌어올린 여정이 공유됐다.
- 에이전트는 사용자의 질문만 처리하는 것이 아니라 Airbridge의 마케팅 데이터와 설정 상태를 이해하고 필요한 기능을 호출한다.
- MCP는 SaaS 기능과 외부 도구를 에이전트가 호출할 수 있게 하는 연결 계층으로 설명됐다.
- Amazon Bedrock AgentCore는 Gateway, Runtime, Memory, 도구 호출, 평가와 운영 요소를 묶어 에이전트형 SaaS 구현 기반으로 제시됐다.
- 정확도, 비용, 지연시간, 보안, 잘못된 도구 호출, 데이터 유출 책임이 에이전틱 SaaS 설계의 핵심 이슈로 다뤄졌다.

## 세부 내용

### RAG 챗봇에서 에이전트로

AB180은 Airbridge라는 마케팅 솔루션을 운영하면서 고객이 제품 기능, 캠페인 성과, 설정 방법을 더 쉽게 이해하도록 ASK Airbridge를 만들었다. 초기 버전은 문서를 찾아 답변하는 RAG 챗봇에 가까웠고, 고객의 실제 업무 맥락을 충분히 이해하지 못하는 경우가 많았다.

발표에서는 낮은 유효 답변율이 단순 모델 성능 문제만은 아니었다고 설명했다. B2B SaaS 고객은 일반적인 설명보다 자신의 계정, 캠페인, KPI, 설정 상태에 맞는 답을 원한다. 따라서 챗봇이 문서를 검색하는 수준을 넘어 제품 안의 데이터와 기능을 실제로 다룰 수 있어야 했다.

### SaaS 에이전틱 AI의 설계

Airbridge Pilot은 사용자의 목표를 이해하고 필요한 도구를 선택해 실행하는 에이전트형 제품 경험을 지향한다. 예를 들어 마케팅 담당자가 캠페인 성과를 묻거나 특정 설정을 요청하면, 에이전트는 Airbridge 데이터와 기능을 참조해 분석과 실행을 이어간다.

발표에서는 에이전틱 AI를 맥락을 기억하고, 필요한 도구를 선택하고, 외부 환경에 행동을 내보내는 시스템으로 설명했다. SaaS 제품에서는 이 능력이 제품 UI의 일부가 아니라 제품 사용 방식 자체를 바꾸는 요소가 된다.

### MCP와 AgentCore

MCP는 Airbridge 기능과 외부 도구를 에이전트가 표준화된 방식으로 호출하게 하는 연결 구조로 제시됐다. 이를 통해 에이전트가 API, CLI, 내부 기능을 조합해 고객 업무 흐름에 개입할 수 있다.

Amazon Bedrock AgentCore는 에이전트 운영에 필요한 구성 요소를 제공하는 기반으로 소개됐다. Gateway는 도구 연결과 호출 경로를 관리하고, Runtime은 에이전트 실행 환경을 제공하며, Memory는 고객 맥락을 이어가는 데 활용된다. 평가 체계는 에이전트가 실제로 유효한 답과 행동을 만들어내는지 검증하는 장치로 다뤄졌다.

### 운영과 책임

에이전트가 제품 안에서 행동하기 시작하면 SaaS 사업자가 고려해야 할 책임도 커진다. 발표에서는 정확도와 비용뿐 아니라 잘못된 도구 호출, 권한 초과, 고객 데이터 노출, 응답 지연 같은 문제가 모두 제품 설계의 일부가 된다고 설명했다.

AB180은 에이전트의 성과를 비용 대비 효과로 평가해야 한다고 봤다. 고객의 시간을 줄이고 업무 성공률을 높이는지, 실패했을 때 사람이 개입할 수 있는지, 보안 요건을 만족하는지가 에이전틱 SaaS의 품질 기준이 된다.

## 정리

이 세션의 핵심은 SaaS의 경쟁력이 편리한 화면에서 에이전트가 실제 업무를 수행할 수 있는 기반으로 이동하고 있다는 점이다. AB180은 RAG 챗봇의 한계를 인정하고, 제품 데이터와 도구 호출을 결합한 Airbridge Pilot으로 고객의 마케팅 업무 수행 경험을 바꾸려 했다.

발표는 에이전틱 AI가 단순한 답변 기능이 아니라 SaaS 제품의 아키텍처, 권한, 평가, 책임 구조를 함께 바꾸는 변화라는 점을 잘 보여줬다.
