# AWS Summit Seoul 2026 참석 정리: 카카오페이 AX TF 관점

이번 Summit에서 가장 크게 남은 점은 AI 도구 자체보다 운영 가능한 AX 구조였다. Claude Code, Cursor, Amazon Q, Bedrock, 사내 LLM 도구를 잘 쓰는 것은 이미 출발선에 가깝다. 다음 과제는 개인의 생산성 향상을 전사적으로 재사용 가능한 스킬, 안전한 개발자 AI 플랫폼, AI-ready data, AgentOps 체계로 바꾸는 것이다.

카카오페이는 금융 서비스 회사다. AX를 빠르게 확산하더라도 고객 정보, 금융 거래, 내부 정책, 감사 로그, 권한 관리가 함께 설계되어야 한다. Summit에서 본 사례들도 결국 같은 방향을 가리켰다. 잘 만든 AI 기능보다 중요한 것은 안전하게 반복 운영되는 구조다.

## 1. 스킬허브는 프롬프트 저장소가 아니다

GS SHOP의 영상 기반 상품 추천 사례는 스킬허브의 방향을 잘 보여줬다. 영상 전체를 요약하는 것이 아니라 추천에 필요한 상품 속성, 장면, 스타일, 분위기, 구매 신호를 뽑아냈다. AI가 만든 결과가 업무에서 다시 쓰일 수 있는 데이터가 되어야 가치가 생긴다.

카카오페이에서도 혜택 추천, 금융 상품 추천, 가맹점 추천, 이벤트 타겟팅, 고객 안내 문구 생성은 단순 생성형 AI 문제가 아니다. 어떤 신호를 추출할지, 어떤 데이터와 연결할지, 어떤 기준으로 검증할지 먼저 정리해야 한다.

스킬허브에 필요한 기본 항목은 다음과 같다.

- 입력: 어떤 문서, 데이터, 요청을 받는가
- 출력: 어떤 형식의 결과를 만드는가
- 참조 데이터: 어떤 시스템과 지식베이스를 사용하는가
- 검증 기준: 결과가 맞는지 어떻게 확인하는가
- Owner: 누가 관리하고 개선하는가
- 권한: 누가 사용할 수 있는가
- Human review: 사람 승인 없이 사용 가능한가

## 2. 금융권 개발자 AI 플랫폼은 속도와 통제를 같이 잡아야 한다

빗썸의 Claude Code on Amazon Bedrock 사례가 가장 직접적인 참고 사례였다. 생성형 AI 사용을 막는 것이 아니라 SSO, 프라이빗 네트워크, 감사 로그, 비용 관리, 프롬프트 필터링, 모델 라우팅을 붙여 안전한 사용 경로를 만들었다.

카카오페이도 개발자들이 이미 AI 코딩 도구를 쓰고 있다면, 개인 사용 경험에만 맡기기 어렵다. 개발 속도를 높이면서 금융권 내부통제와 감사 가능성을 만족하는 공통 플랫폼이 필요하다.

우선 검토할 항목은 다음과 같다.

- 사내 계정 기반 인증과 권한 관리
- 외부 모델 사용 시 프라이빗 연결 또는 Bedrock 기반 경로
- 프롬프트와 응답에 대한 보안 필터링
- 코드, 로그, 고객 정보 반출 방지 정책
- 팀/개인별 사용량과 비용 가시화
- 팀별 스킬, 시스템 프롬프트, 개발 표준 공유
- 모델별 사용 정책과 라우팅 기준

## 3. Agent Builder는 자유도가 아니라 안전한 조합이 핵심이다

바비톡의 AX 여정은 작게 시작해서 실제 문제를 빠르게 검증하는 방식이 인상적이었다. 리뷰 검수, 검색, 상담, K-beauty 여행 가이드처럼 업무 단위가 명확했고, 에이전트도 그 업무를 해결하는 방향으로 확장됐다.

카카오페이에서 비개발자용 Agent Builder를 만든다면 모든 기능을 자유롭게 열기보다 검증된 블록을 조합하게 해야 한다. 승인된 스킬, 승인된 데이터 커넥터, 허용된 액션을 조합하는 방식이 적합하다.

초기에는 조회형, 요약형, 분류형, 초안 작성형 에이전트부터 시작하는 것이 안전하다. 실행형 에이전트는 승인 절차, 실행 로그, 권한, 롤백 기준이 준비된 뒤에 열어야 한다.

## 4. AI-ready data가 없으면 AX는 PoC에서 멈춘다

AI Day에서 반복된 메시지는 데이터였다. 에이전트가 업무를 하려면 데이터의 위치, 의미, 권한, 최신성, 출처를 알아야 한다. 데이터가 정리되지 않으면 RAG도 Agent Builder도 데모 수준에서 멈춘다.

카카오페이에는 고객 데이터, 거래 데이터, 내부 정책, 개발 문서, 장애 이력, 고객센터 지식, 금융 상품 설명, 리스크 정책이 있다. 민감도와 권한이 모두 다르기 때문에 “AI가 봐도 되는 데이터”와 “절대 연결하면 안 되는 데이터”를 먼저 나눠야 한다.

AX TF에서 먼저 정리할 기준은 다음과 같다.

- AI 사용 가능 데이터 등급
- 부서별 데이터 Owner
- 문서 최신성 관리 방식
- RAG 검색 시 권한 필터링 기준
- 답변에 출처를 남기는 방식
- 고객 정보와 금융 거래 정보의 차단 기준

## 5. AIOps와 AgentOps는 빠르게 효과를 볼 수 있다

삼성 어카운트 AIOps 세션은 대규모 서비스 운영에서 AI가 현실적인 가치를 만들 수 있음을 보여줬다. 장애 이벤트를 묶고, 영향 범위를 좁히고, 원인 후보와 조치 후보를 제시하는 흐름은 카카오페이에도 잘 맞는다.

결제, 송금, 인증, 증권, 보험, 가맹점 서비스는 서로 연결되어 있다. 장애가 발생했을 때 고객 영향 추정, 원인 후보 정리, 공지 초안, 회고 문서 초안 작성은 AI가 도울 수 있는 영역이다.

다만 운영 에이전트는 처음부터 자동 조치로 가면 위험하다. 분석, 요약, 추천, 문서화에서 시작하고 사람 승인 단계를 두는 것이 현실적이다.

## 6. 내부 업무 플랫폼은 작은 실험에서 시작한다

완성차 지능형 상품 전략 플랫폼 세션은 여러 데이터 소스를 묶어 의사결정을 돕는 내부 플랫폼의 가능성을 보여줬다. 자동차 도메인은 다르지만, 상품 전략과 시장 데이터를 연결해 담당자가 직접 탐색한다는 구조는 핀테크에도 적용할 수 있다.

카카오페이에서는 금융 상품, 혜택, 가맹점, 사용자 행동, 리스크 지표, 캠페인 성과를 연결한 내부 전략 에이전트를 생각해볼 수 있다. 상품, 마케팅, 제휴, 운영 담당자가 직접 질문하고 초안을 얻되, 민감 데이터 접근과 결과 검증은 플랫폼이 통제하는 구조가 필요하다.

20만 Amazonian의 AI 내재화와 Quick Desktop 사례도 같은 방향이었다. 각자가 AI 도구를 흩어져 쓰는 방식은 빠르지만 조직 역량으로 남기 어렵다. 승인된 데이터, 승인된 도구, 스킬, 로그, 비용 관리가 한곳에 모여야 한다.

## 7. 실제로 들은 세션에서 남은 포인트

GS SHOP 세션에서는 추천을 위한 신호 추출이 가장 기억에 남았다. 카카오페이의 추천 영역도 좋은 메타데이터와 검증 가능한 근거가 있어야 한다.

K-POP 글로벌 라이브 세션에서는 AI 자막보다 운영 안정성이 크게 보였다. 금융 서비스의 AI 기능도 장애 전환, 품질 폴백, 비용 통제와 함께 설계되어야 한다.

바비톡 세션에서는 작게 시작하는 방식이 좋았다. AX TF도 거대한 플랫폼보다 반복 업무 하나를 실제로 줄이는 작은 성공을 먼저 만들어야 한다.

빗썸 세션은 핀테크 관점에서 가장 직접적이었다. 개발자 AI 도구를 안전하게 쓰게 만드는 내부 플랫폼은 카카오페이에서도 우선순위가 높다.

삼성 어카운트 AIOps 세션은 운영 분석과 조치 후보 추천의 가능성을 보여줬다. 카카오페이의 복잡한 서비스 운영에도 적용 여지가 크다.

완성차 지능형 상품 전략 플랫폼 세션은 내부 의사결정 플랫폼의 가능성을 보여줬다. 금융 상품, 혜택, 제휴, 사용자 행동 데이터를 연결하는 전략 에이전트로 확장할 수 있다.

20만 Amazonian과 Quick Desktop 세션은 AI 내재화가 개인 도구 사용을 넘어 회사가 승인한 업무 환경과 스킬 체계로 가야 한다는 점을 보여줬다.

## 바로 논의할 주제

AX TF에서 먼저 잡을 주제는 네 가지다.

1. 사내 스킬허브를 어떤 업무 단위로 정의할 것인가
2. 개발자 AI 도구를 금융권 기준에 맞게 어떻게 안전하게 제공할 것인가
3. AI-ready data와 권한 체계를 어디까지 먼저 정리할 것인가
4. AgentOps와 AIOps를 어떤 업무부터 작게 실험할 것인가

결론은 단순하다. AI 도구를 더 많이 쓰는 것보다, AI가 안전하게 일할 수 있는 업무 구조를 만드는 것이 AX TF의 역할이다.
