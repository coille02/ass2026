# 중앙대의료원 의료 AI 관점 참고

연결 세션: [중앙대의료원_의료진이 직접 만드는 의료 AI](../sessions/industry_day/sel-wps102.md)

## 정리 목적

이 페이지는 중앙대의료원 의료 AI 사례를 AX TF 관점에서 다시 읽기 위한 참고 문서다. 핵심은 의료 AI를 외부 솔루션 도입 문제가 아니라, 현장을 가장 잘 아는 사람이 직접 문제를 정의하고 작은 도구를 만들어보는 전환으로 바라본다는 점이다.

기존 세션 정리에서는 중앙대의료원이 의료진과 직원이 직접 AI 도구를 만드는 경험을 통해 반복 업무를 줄이고, 환자와 치료 본질에 더 집중할 가능성을 보여줬다고 정리했다. 이 관점은 사내 AX 과제 발굴에도 그대로 연결된다.

## 인상 깊은 관점

### 1. 현장을 아는 사람이 문제를 가장 잘 정의한다

의료 AI의 어려움은 기술이 부족해서만 생기는 것이 아니다. 의료 현장은 데이터가 민감하고, 용어와 판단 기준이 복잡하며, 작은 오류가 큰 위험으로 이어질 수 있다. 그래서 외부에서 만든 범용 도구를 그대로 들여오는 방식만으로는 한계가 있다.

중앙대의료원 사례에서 인상 깊은 점은 의료진과 직원이 직접 문제를 정의했다는 점이다. 어떤 업무가 반복되는지, 어디에서 휴먼 에러가 생길 수 있는지, 어떤 정보가 안전하게 정리되어야 하는지는 현장에 있는 사람이 가장 잘 안다.

AX TF에서도 부서별 과제를 발굴할 때 비슷한 관점이 필요하다. “AI로 무엇을 만들 수 있을까”보다 “현장에서 매일 반복되고, 사람이 기준을 알고 있으며, 작게 실험할 수 있는 문제는 무엇인가”를 먼저 물어야 한다.

### 2. 작고 명확한 반복 업무가 좋은 출발점이다

중앙대의료원 세션에서는 복약 이력 정리, 연구 업적 입력 자동화 같은 사례가 언급됐다. 거대한 의료 AI 모델을 만드는 것보다, 의료진과 직원이 매일 겪는 반복 업무를 줄이는 작은 도구가 현실적인 출발점이었다.

이 관점은 AX TF의 과제 선정 기준에도 도움이 된다. 처음부터 큰 Agent Builder나 전사 플랫폼을 완성하려고 하기보다, 작고 명확한 문제를 골라 빠르게 검증해야 한다.

좋은 출발점은 다음 조건을 가진 업무다.

- 반복 빈도가 높다.
- 사람이 이미 판단 기준을 알고 있다.
- 입력과 출력이 비교적 명확하다.
- 실패해도 사람이 검토하고 수정할 수 있다.
- 효과를 시간 절감, 오류 감소, 문서 품질 개선 등으로 측정할 수 있다.

### 3. 보안과 민감정보는 멈춤의 이유가 아니라 설계의 전제다

의료 데이터는 민감도가 높다. 그래서 의료 AI에서는 보안, 접근 권한, 감사, 검증이 처음부터 설계에 들어가야 한다. 중앙대의료원 사례에서 중요한 메시지는 민감정보 때문에 AI를 하지 말자는 것이 아니라, 민감정보를 다루는 방식 자체를 설계해야 한다는 점으로 읽힌다.

이 관점은 금융 서비스나 내부 업무 자동화에도 중요하다. AX 과제에서 고객 정보, 거래 정보, 내부 정책, 운영 로그, 개발 문서가 연결될수록 권한과 감사 가능성이 중요해진다. 현업이 직접 도구를 만들 수 있게 하더라도, 안전한 데이터 경계와 승인된 도구 목록이 함께 있어야 한다.

### 4. 현업 주도 개발에는 가이드와 멘토링이 필요하다

중앙대의료원 사례에서는 개발 경험이 없는 의료진도 AWS T&C 프로그램과 Kiro 기반 바이브 코딩을 통해 프로토타입을 만들 수 있음을 보여줬다. 다만 이것은 “누구나 마음대로 만들면 된다”는 뜻이 아니다.

현업 주도 개발이 성공하려면 다음 요소가 함께 필요하다.

- 문제 정의 템플릿
- 입력/출력 명세
- 사용할 수 있는 데이터 범위
- 금지 데이터와 금지 액션
- 검증 기준
- 배포 전 리뷰
- 운영 중 모니터링
- 기술 멘토 또는 플랫폼팀 지원

이 구조가 있어야 비개발자도 안전하게 실험하고, 좋은 결과물을 조직 자산으로 남길 수 있다.

## AX TF에 가져갈 점

중앙대의료원 사례를 보면서 AX TF에서 참고할 만한 점은 세 가지다.

첫째, 과제 발굴은 현업의 작은 반복 업무에서 시작해야 한다. 의료진이 복약 이력이나 연구 업적 입력 같은 구체적인 문제를 직접 잡았듯이, 각 부서에서도 반복적으로 시간을 쓰는 업무를 먼저 찾아야 한다.

둘째, 현업이 직접 만들 수 있는 환경을 주되, 안전한 경계를 함께 제공해야 한다. Agent Builder나 Skill Hub가 필요하다면 자유로운 생성 환경이 아니라, 승인된 데이터와 도구, 검증된 스킬을 조합하는 방식이어야 한다.

셋째, Skill Hub는 현업의 문제 해결 경험을 자산화하는 장치가 되어야 한다. 의료진이 만든 복약 정리 도구처럼, 한 팀에서 만든 작은 스킬이 다른 팀에서도 재사용될 수 있도록 입력, 출력, 데이터, 권한, 검증 기준을 함께 기록해야 한다.

## 사내 적용 아이디어

- 현업 부서별로 “반복 업무 3개”를 수집한다.
- 각 업무에 대해 입력, 출력, 판단 기준, 검증 방법을 적게 한다.
- 민감정보 여부와 필요한 권한을 함께 표시한다.
- 조회형, 요약형, 분류형, 초안 작성형 업무부터 PoC 대상으로 삼는다.
- PoC 결과가 좋으면 Skill Hub에 등록하고, Owner와 운영 기준을 붙인다.
- 비개발자도 사용할 수 있는 공통 스킬을 먼저 만든다.

예를 들면 다음과 같은 스킬이 출발점이 될 수 있다.

- 회의록 요약 스킬
- 정책 문서 검색 스킬
- 보고서 초안 작성 스킬
- 회사 포맷 기반 PPT 생성 스킬
- 고객 문의 분류 스킬
- 운영 이슈 회고 초안 작성 스킬

## 추가 확인할 점

현재 페이지는 기존 중앙대의료원 세션 정리와 참고 영상 링크를 바탕으로 작성했다. 영상에서 구체적으로 강조한 표현이나 추가 사례가 있다면, 이후 다음 내용을 보강하면 좋다.

- 발표자가 강조한 핵심 문장
- 의료진이 직접 만든 프로토타입의 구체 사례
- Kiro 또는 바이브 코딩을 사용한 실제 흐름
- 보안과 민감정보 처리 방식
- AX TF 공유 시 인용할 만한 표현

## 한 줄 정리

중앙대의료원 사례는 AX가 현업을 대체하는 일이 아니라, 현업이 직접 문제를 정의하고 안전한 경계 안에서 작은 AI 도구를 만들어보게 하는 일이라는 점을 보여준다.
