## sel-ind201

**title/time/track/speakers**  
- 제목: [삼성전자 I 우아한형제들 I TwelveLabs] 혁신가와 리더의 대담 - AI로 이끄는 비즈니스 혁신
- 시간: 2026-05-20 16:10-16:50 KST
- 트랙: AWS Summit Seoul - Track 1
- 발표자: 김기완(AWS 코리아 테크리더, AWS), 고명석(CTO, 우아한형제들), 서치영(부사장, 삼성전자), 이승준(Aiden Lee, CTO, TwelveLabs)

**핵심 요약**  
서로 다른 산업과 규모의 기술 리더들이 AI 시대의 리더십, 조직 변화, 생산성 전환을 패널 형식으로 논의했다. 공통 메시지는 리더가 답을 내려주는 방식에서 벗어나 직접 AI를 써보고, 조직이 실험하고 학습하는 구조를 만들어야 한다는 점이었다. AI 도입의 핵심은 모델 성능만이 아니라 신뢰성, 통제 가능성, 실패를 빠르게 발견하고 바로잡는 운영 방식으로 옮겨가고 있었다. 세션 말미에는 “에이전트와 함께 일하는 조직”의 형태 자체가 앞으로의 큰 과제가 될 것이라고 정리했다.

**주요 포인트**
- AI 제품을 만드는 것과 AI 네이티브 조직을 만드는 것은 다른 문제이며, 개인 생산성과 조직 생산성은 별도의 설계가 필요하다.
- 기업 고객은 “AI에게 맡길 수 있는가”보다 “AI를 얼마나 통제하고 설명할 수 있는가”를 더 중요하게 본다.
- 리더는 AI를 전략 슬라이드의 주제로만 다루지 말고 직접 사용해 생산성 변화와 한계를 체감해야 한다.
- 개발자뿐 아니라 비개발자도 AI 도구를 업무에 적용할 수 있도록 교육, 공유, 사례 전파가 필요하다.
- AI 시대의 조직은 사람 중심의 팀 구조에서 에이전트와 사람이 함께 일하는 구조로 재설계될 가능성이 크다.

**AWS/기술 키워드**  
Amazon Bedrock, Foundation Model, AI Agent, AI Native Organization, Reliability, Human-in-the-loop, 생산성 혁신, 리더십 전환

**현장 메모로 남길 점**  
패널 전체가 기술보다 “조직 운영과 리더의 실사용 경험”을 더 강조했다. 블로그에서는 각 기업 사례를 병렬로 나열하기보다 “AI 시대 리더의 역할이 답변자에서 실험 설계자로 바뀐다”는 관점으로 묶으면 좋다.

**블로그용 한줄**  
AI 혁신의 출발점은 더 좋은 모델보다, 리더가 먼저 써보고 조직이 함께 학습하는 일하는 방식의 변화였다.

## sel-ind229

**title/time/track/speakers**  
- 제목: [롯데백화점] AI로 잇는 쇼핑 경험: 롯데백화점의 AI 에이전트 구축기
- 시간: 2026-05-20 16:10-16:50 KST
- 트랙: AWS Summit Seoul - Track 2
- 발표자: 소찬호(솔루션즈 아키텍트, AWS), 홍병우(팀장, 롯데백화점)

**핵심 요약**  
롯데백화점은 모바일 앱 기반 쇼핑 경험을 단순 FAQ 챗봇에서 고객 의도를 이해하고 행동하는 AI 컨시어지 “더스틴”으로 확장한 과정을 공유했다. 발표는 챗봇에서 LLM, 다시 AI 에이전트로 진화한 흐름을 짚고, 700만 고객 규모의 리테일 서비스에서 정보 파편화, 반복 문의, 최신 데이터 반영 문제를 어떻게 풀었는지 설명했다. 더스틴은 고객 경험뿐 아니라 직원 업무 효율과 파트너 협업까지 겨냥한 운영 엔진으로 설계됐다. 비용과 응답 속도를 위해 정적 정보와 동적 정보를 분리하고, 필요한 필드만 LLM 컨텍스트에 넣는 최적화가 강조됐다.

**주요 포인트**
- 롯데백화점의 AI 미션은 AI 자체가 목적이 아니라 고객 경험, 직원 효율, 파트너 협업을 높이는 도구로 쓰는 것이다.
- 더스틴은 매장 위치, 행사, 운영 정보, 외국어 응대 등 백화점 특유의 복잡한 정보를 고객 맥락에 맞게 연결한다.
- 아키텍처는 CloudFront와 웹 애플리케이션 진입, 데이터/검색 계층, 에이전트 상태 관리, 프론트엔드 카드 UI 분리를 포함한다.
- 정적 정보는 앞단에, 자주 바뀌는 동적 정보는 뒤단에 두어 입력 토큰과 지연시간을 줄였다.
- 검색 결과 전체를 LLM에 넣지 않고 답변 생성에 필요한 핵심 필드만 사용해 비용, 품질, 환각 방지를 동시에 고려했다.

**AWS/기술 키워드**  
AI Agent, LLM, Amazon S3, Amazon CloudFront, OpenSearch, RAG, 에이전트 상태 관리, 토큰 최적화, 다국어 쇼핑 컨시어지

**현장 메모로 남길 점**  
“정적인 것은 앞에 두고 동적인 것은 뒤에 둔다”는 설계 원칙이 실무적으로 좋았다. 리테일 AI 사례를 쓸 때 고객-facing 챗봇이 아니라 데이터 운영, UI 상태, 비용 최적화까지 포함한 제품화 사례로 다루면 풍성하다.

**블로그용 한줄**  
롯데백화점의 더스틴은 FAQ 챗봇을 넘어, 백화점의 복잡한 현장 데이터를 고객 경험으로 바꾸는 AI 컨시어지였다.

## sel-ind209

**title/time/track/speakers**  
- 제목: [빗썸] 빗썸은 생성형 AI를 어떻게 안전하게 운영하는가: Claude Code on Amazon Bedrock
- 시간: 2026-05-20 16:10-16:50 KST
- 트랙: AWS Summit Seoul - Track 3
- 발표자: 마상범(솔루션즈 아키텍트, AWS), 고주호(팀장, 빗썸), 백길선(팀장, 빗썸)

**핵심 요약**  
빗썸은 Claude Code를 금융권 환경에서 통제 가능하게 운영하기 위해 Amazon Bedrock 기반의 보안 아키텍처를 구축한 경험을 공유했다. 핵심 요구사항은 SSO 인증, 프라이빗 네트워크, 감사 로그, 팀/개인별 비용 관리, 프롬프트 필터링이었다. 발표는 IAM, SCP, CloudTrail, CloudWatch, Direct Connect, LLM Gateway 등을 조합해 개발자 경험을 유지하면서도 규제와 내부통제를 만족시키는 구조를 설명했다. 향후에는 멀티 모델 라우팅, 팀별 시스템 프롬프트/스킬 공유, 개발-배포-운영 전주기 AI 자동화를 확대할 계획이라고 밝혔다.

**주요 포인트**
- 기업 및 금융권에서 Claude Code 같은 강력한 도구는 보안, 규제, 비용 통제 없이 개인 구독형으로 방치할 수 없다.
- API 키 방식 대신 사내 계정 체계와 연동되는 SSO 기반 인증과 권한 회수가 필요하다.
- 개발자 PC의 요청은 Direct Connect와 LLM Gateway를 거쳐 Bedrock Runtime으로 이동하며 인터넷 구간을 제거했다.
- IAM, SCP, CloudTrail, CloudWatch로 접근 제어, 감사 추적, 사용량 관리를 통합했다.
- Claude 스킬과 프롬프트를 조직 카탈로그로 축적해 개인의 AI 활용 노하우를 조직 자산으로 전환하려 했다.

**AWS/기술 키워드**  
Amazon Bedrock, Claude Code, IAM, SCP, AWS Direct Connect, AWS PrivateLink, CloudTrail, CloudWatch, LLM Gateway, Guardrails, SSO, 멀티 모델 라우팅

**현장 메모로 남길 점**  
세션의 핵심 문장은 “보안은 제품이 아니라 설계”로 정리된다. 금융권 생성형 AI 도입 글에서는 개발 생산성보다 먼저 인증, 네트워크 경로, 감사, 비용, 프롬프트 통제를 아키텍처 요구사항으로 잡은 점을 강조하면 좋다.

**블로그용 한줄**  
빗썸의 Claude Code 도입기는 금융권 생성형 AI가 빠르게 쓰이려면 먼저 안전하게 설계돼야 한다는 것을 보여줬다.
